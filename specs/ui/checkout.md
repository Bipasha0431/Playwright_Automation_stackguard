# Checkout Test Plan

## Feature summary

The Swag Labs checkout has three pages: Your Information (/checkout-step-one.html, first name, last name, postal code), Overview (/checkout-step-two.html, items, payment and shipping lines, item total, tax, total, Finish) and Complete (/checkout-complete.html, confirmation and Back Home). This plan covers the happy path, order maths, form validation, odd input, the empty cart, cart changes before checkout, Cancel and browser navigation, direct URL access, signed-out access and the checkout quirks of problem_user and error_user. The cart page contents, the cart Checkout button, adding from the product list, login and logout are covered by other plans and are out of scope.

## Application URL / environment

- URL under test: https://www.saucedemo.com (checkout pages /checkout-step-one.html, /checkout-step-two.html, /checkout-complete.html), public production demo
- Every scenario starts in a fresh browser context, signed in on the product list with an empty cart, unless the row says otherwise.

## Credentials used

- standard_user (main scenarios), problem_user and error_user (one row each)
- All share the same password: secret_sauce

## Open questions / notes

- Confirmed defects: empty cart checkout (CHK-006), Back after finishing allows another order (CHK-007), whitespace-only names and postal code accepted (CHK-004) and direct URLs to step two and complete open without an order (CHK-012).
- Postal code accepts letters and symbols, and no field has a length limit (CHK-005); product decision needed on required format and limits. Not marked as a bug.
- Overview Cancel goes to the product list while step one Cancel goes to the cart (CHK-009); confirm whether intended.
- Entered customer details are never shown on the overview or confirmation, so safe rendering of the typed text could only be checked as "no alert, nothing displayed".
- Typed values are lost after Cancel and reload (CHK-010); confirm whether intended. Browser Back from the overview is not covered: the browser restores the typed values on Back, so the result depends on how the page is reached and is not a reliable check.
- Tax and totals were verified earlier on all 63 carts (standard_user) 
- Unverified: quantity changes (none possible), mobile layout, accessibility, keyboard-only use, other browsers, visual_user and performance_glitch_user, locked_out_user.
