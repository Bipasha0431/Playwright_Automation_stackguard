# Inventory Test Plan

## Feature summary

The Swag Labs product list (inventory page) shows six products with image, name, description, price and an Add to cart / Remove button, a sort dropdown and a cart badge. This plan covers the default list, adding and removing products from the list, sorting, Reset App State effect on the list, opening product detail pages and keeping the badge in sync, two edge cases (double-click, nonexistent product id) and the list-specific quirks of problem_user and error_user. Login, cart page, checkout and logout are out of scope and have their own plans.

## Application URL / environment

- URL under test: https://www.saucedemo.com/inventory.html (public production demo)
- Every scenario starts in a fresh browser context, signed in on the product list with an empty cart, unless the row says otherwise.

## Credentials used

- standard_user (main scenarios), problem_user, error_user
- All share the same password: secret_sauce

## Open questions / notes

- Sort choice is not kept after reload (INV-005), and Reset App State does not reset the button labels until the page is reloaded (INV-006). Product decision needed on whether both are intended. Both are recorded as observed, not marked as bugs.
- A nonexistent product id shows an "ITEM NOT FOUND" page instead of redirecting (INV-009). The page text also contained an "Add to cart" button and placeholder text, not verified further. The console error content was not analysed.
